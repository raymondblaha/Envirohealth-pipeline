# Database Design

This project uses a layered PostgreSQL model:

```text
CSV files
   -> raw
   -> core
   -> analytics
```

The goal is to keep source ingestion separate from cleaned relational entities and analysis-ready outputs.

## Schemas

- `raw`: source-shaped tables loaded from CSV files with minimal transformation.
- `core`: standardized relational tables with stable keys, typed columns, and documented relationships.
- `analytics`: SQL views and derived tables for analysis, notebooks, and reporting.

## Key Discovery Results

Generated by:

```bash
python -m envirohealth.key_discovery
```

Current report:

- `cdc_places_county`: `LocationID + MeasureId + Year + DataValueTypeID` is unique.
- `epa_county_aqi`: `State + County + Year` is unique.
- `epa_cbsa_aqi`: `CBSA Code + Year` is unique.
- `epa_monitor_concentration`: `State Code + County Code + Site Num` identifies a physical monitor site, but not a measurement row.
- EPA monitor site attributes are stable for `State Code + County Code + Site Num` across the current 2021-2022 files.

EPA measurement rows need special handling. Candidate measurement keys are unique by row, but `Pollutant Standard` and `Method Name` contain many null values. PostgreSQL allows nulls in unique constraints but not primary-key columns, so the core measurement table should use a surrogate key plus a supporting unique index after null semantics are finalized.

## Geography Strategy

CDC PLACES has `LocationID`, which can be standardized to five-digit county FIPS:

```text
county_fips = LPAD(LocationID, 5, '0')
```

EPA monitor data has `State Code` and `County Code`, which can also create county FIPS:

```text
county_fips = LPAD(state_code, 2, '0') || LPAD(county_code, 3, '0')
```

EPA county AQI summary files only provide state and county names. Those rows should be mapped to `core.counties` through a validated name-resolution step rather than joined directly to CDC by county name.

## Analytical Layer

The first analysis-ready object should be:

```sql
analytics.county_environment_health
```

This view will join county-level pollution exposure features to county health measures after the core tables are loaded and validated.
